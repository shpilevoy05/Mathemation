# Матемация — MVP

Сервис управляемой подготовки к ЕГЭ по профильной математике: входная
диагностика → карта знаний с забыванием → персональный план → уроки и задачи
(«дорожка») → отработка ошибок → пробники с таймером → экспертная проверка
второй части → прогноз балла с потолком и «рычагами» → weekly-отчёт родителю.

Реализованы функции уровней **Must** и **Should** из продуктового видения.

## Стек
Django + DRF (модульный монолит), PostgreSQL (dev/tests — SQLite), Celery + Redis.

## Запуск
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo  # граф, задачи, траектории, пользователи
.\.venv\Scripts\python.exe manage.py runserver
# фоновые задачи (забывание, weekly-отчёты, простой, просроченные повторы):
celery -A config worker -B
```
После `seed_demo` доступны пользователи `student`, `parent`, `expert`
(пароль `demo12345`). PostgreSQL включается переменными
`POSTGRES_DB/USER/PASSWORD/HOST/PORT`.

## Функции и где они живут

### Must
- **Входное тестирование** — на выбор полный пробник или короткий срез по
  ключевым узлам; по результату сеется карта знаний, считается стартовый балл
  и строится план (`apps/diagnostics`).
- **Карта знаний** — граф гранулярных навыков с рёбрами-зависимостями.
  Узел: % освоения, номера ЕГЭ, дата последней практики, индикатор
  забывания, состояния «закрыто / можно начинать / в процессе / освоено /
  подзабылось»; внутри — теория, история ошибок, переход к урокам.
  Забывание пересчитывается идемпотентно после каждого занятия/пробника и
  ночным джобом; «остывший» узел сам возвращается в план. Оверлей
  `?overlay=ceiling` честно подсвечивает узлы, до которых при текущем темпе
  не успеть (`apps/knowledge`).
- **Персональный план** — топология зависимостей + вес в баллах; резкие
  изменения (плохой пробник, 3-я ошибка по теме, простой 2+ недели) логируются
  как major и показываются большим всплывающим окном до подтверждения;
  «Карточка изменений плана» — `GET /api/plan/changes/` (`apps/planning`).
- **Именованные траектории 78+/84+/90+** — диагностика назначает сценарий по
  цели ученика; плохой пробник, три ошибки по узлу или простой 14+ дней могут
  понизить траекторию, два устойчиво сильных пробника — повысить. Каждый
  переход хранит причины, конкретные recovery-действия и требует подтверждения:
  `GET /api/trajectory/`, `POST /api/trajectory/transitions/<id>/ack/`.
- **План на день/неделю** — чек-лист при входе (всплывающее окно + кнопка
  «показать снова»), отметка выполнения пункта.
- **Пробники и проверка второй части** — пробник в формате ЕГЭ с таймером
  (235 мин); часть 1 проверяется автоматически, часть 2 — фото/скан уходит
  живому эксперту (SLA 48 ч), эксперт ставит баллы по критериям и комментирует,
  «где потерян балл». Когда все работы проверены, пробник закрывается, итог
  переводится в тестовый балл по таблице и перекалибровывает прогноз
  (`apps/mocks`, `apps/expert_review`).
- **Отработка** — «полка ошибок»: каждая ошибка привязана к узлу, повторы по
  интервальной схеме 1/3/7/30 дней; перед новой темой подмешиваются 1-2 задачи
  на старые слабые места; закрытая петля отвечает «эту ошибку ты уже не
  делаешь». Ошибки типизированы (`wrong_method`, `rubric_miss` и др.); экспертные
  `error_tags` второй части переносятся в backlog, а weekly-отчёт показывает
  распределение по типам (`apps/practice`, `apps/expert_review`, `apps/progress`).
- **Прохождение задач** — «дорожка»: темы разделены цветами, точки уроков и
  практики, отдельные точки отработки и пробников — `GET /api/track/`
  (`apps/content`).

### Should
- **Прогноз балла** — mastery → ожидаемый первичный → тестовый по таблице
  перевода (конфиг на год, `PRIMARY_TO_SCALED`); после каждого пробника
  предсказание сверяется с фактом и калибруется (EMA). «Рычаги»:
  `GET /api/forecast/?weekly_hours=10&exam_date=...` — ползунок темпа и дата
  двигают потолок (`apps/progress`).
- **ИИ-наставник** — чат внутри задачи: ведёт наводящими вопросами по шагам
  проверенного разбора (`reference_solution`), не выдаёт готовый ответ,
  помечает неуверенность, после 2 подсказок предлагает живого преподавателя;
  отключён на пробниках/диагностике/отработке. Провайдер выбирается настройкой
  `AI_MENTOR_PROVIDER` (LLM подключается без изменения кода). Лог виден
  родителю: `GET /api/parent/ai-log/`, счётчик подсказок — в weekly-отчёте
  (`apps/ai_mentor`).
- **Append-only событийный лог** — попытки, подсказки, диагностики, пробники,
  экспертные проверки, изменения плана, повторы и переходы траекторий пишутся
  через единую сервисную точку без имён и e-mail (`apps/events`).

## Структура
- `apps/accounts` — User, StudentProfile (+калибровка прогноза), ParentProfile
- `apps/knowledge` — TopicCluster (цвет, вес), KnowledgeNode (номера ЕГЭ),
  KnowledgeDependency, SkillMastery (пик/забывание), decay-джоб
- `apps/content` — Lesson, TheoryBlock, Assignment (эталонный разбор), дорожка
- `apps/diagnostics` — входная диагностика, посев mastery, построение плана
- `apps/planning` — Trajectory/Transition, StudyPlan/Item, PlanChangeLog, планировщик
- `apps/practice` — Attempt, типизированный MistakeBacklogItem, ReviewSchedule
- `apps/mocks` — MockExam (таймер), MockExamResult (части 1+2, перевод баллов)
- `apps/expert_review` — ExpertReviewRequest: статусы, критерии, SLA
- `apps/progress` — прогноз/потолок/калибровка, ProgressSnapshot, ParentReport
- `apps/ai_mentor` — HintProvider (mock → LLM), сессии и лог для родителя
- `apps/events` — append-only Event и единая точка записи `log_event`
- `apps/web` — многостраничный server-rendered кабинет ученика

API: `/api/...` (session auth), кабинет: `/`, admin (методисты и эксперты): `/admin/`.

## Веб-кабинет ученика

Кабинет работает на Django-шаблонах и ванильном JavaScript без внешних
зависимостей. Общий адаптивный интерфейс находится в `templates/base.html`,
`static/css/app.css` и `static/js/app.js`; интерактивные действия используют
существующий `/api/...` с session auth и CSRF.

- `/` — траектория, прогресс, план дня и обязательные подтверждения изменений;
- `/map/` — карта навыков, включая оверлей потолка;
- `/map/node/<id>/` — теория и история ошибок узла;
- `/track/` — дорожка уроков, практики, отработок и пробников;
- `/lesson/<node_id>/` — занятие с очередью задач и наставником только в lesson-контексте;
- `/practice/backlog/` — полка ошибок и повторы на сегодня;
- `/forecast/` — условный прогноз и потолок с рычагами темпа и даты экзамена.

Вход и выход подключены через Django auth: `/accounts/login/`; после входа
пользователь возвращается в кабинет.
