# Локальный запуск и проверка функционала по ролям

Инструкция от чистого клона до пройденных вручную сценариев каждой роли.
Команды — для Windows PowerShell (основная среда разработки); для bash
отличается только активация окружения и разделители путей.

---

## 1. Подготовка

| Компонент | Зачем | Обязателен |
| --- | --- | --- |
| Python 3.10+ (проверено на 3.13) | сам сервис | да |
| Git | клон и история | да |
| Redis | брокер Celery для фоновых задач | нет — см. §7 |
| PostgreSQL | боевая БД; локально хватает SQLite | нет |

```powershell
git clone <адрес-репозитория> Mathemation
cd Mathemation
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell блокирует `Activate.ps1`, один раз разрешите скрипты:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

## 2. База и демо-данные

```powershell
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

`seed_demo` идемпотентна. Она создаёт: три тарифа, три способа оплаты и акцию
`START10`, 22 узла графа с зависимостями,
22 опубликованных урока (два с видео), 24 задачи, профиль экзамена 2027
из 19 заданий (все размечены узлами), входную диагностику, пробник,
домашку на трёх задачах,
задание дня, пять предметов магазина, одну работу второй части в очереди
эксперта и четырёх пользователей.

| Логин | Роль | Что открыто |
| --- | --- | --- |
| `student` | ученик | кабинет `/` и все ученические страницы |
| `parent` | родитель | `/parent/` по своему ребёнку |
| `expert` | эксперт | `/expert/` — очередь проверки второй части |
| `methodist` | методист | `/methodist/` и панель `/panel/` |

Пароль у всех — `demo12345`. Вход — `http://127.0.0.1:8000/accounts/login/`;
любая закрытая страница сама перебросит туда с параметром `next`.

Регистрация нового ученика идёт только по коду: методист создаёт код в
`/panel/` (раздел «Приглашения»), человек открывает `/invite/` или ссылку
`/invite/<код>/`, заводит логин и пароль и сразу попадает в кабинет. Код
одноразовый и со сроком; ошибка в коде или занятый логин его не сжигают.

## 3. Ученик (`student`)

Кабинет `/`. Проверяйте по порядку — каждый шаг опирается на предыдущий.

1. **Дашборд.** Прогноз показан интервалом, рядом — потолок при текущем темпе,
   стрик, уровень и XP, квесты недели, план на сегодня, отработка. Кнопка
   «Пройти диагностику» ведёт на `/diagnostics/`.
1а. **Диагностика** `/diagnostics/` — список срезов, кнопка «Пройти»,
   прохождение на `/diagnostics/run/<id>/` без таймера. После отправки
   заполняется карта навыков, назначается траектория и строится план;
   результат (верных ответов и оценка балла) остаётся на странице.
2. **Карта навыков** `/map/` — состояния узлов: закрыто, можно начинать,
   в процессе, освоено, подзабылось. Закрытый узел показывает, какого
   пререквизита и до какого процента не хватает. В списке тем навыки, у
   которых задана папка («Отбор корней», «ОДЗ»), собраны под её заголовком с
   общим процентом; сама папка карточкой не является — заниматься по ней
   нечем.
3. **Дорожка** `/track/` — точки уроков и практики по темам, текущая помечена;
   у каждой точки — срок из плана («по плану 21.08» или «просрочено с 18.08»).
3а. **Расписание** `/schedule/` — тот же план на сетке месяца: занятия,
   практика, повторы, дедлайны домашек и дата экзамена. Пункт плана
   переносится перетаскиванием на другой день; в прошлое и за дату экзамена
   перенос не проходит (ответ 409 с объяснением).
4. **Занятие** `/lesson/<node_id>/` проходится тремя этапами со шкалой сверху:
   материал (видео и конспект с кнопкой «Скачать конспект»), задачи по теме,
   отработка ошибок темы. Этап материала закрывает сам ученик кнопкой
   «Разобрался», задачи — решением всех задач, отработка — сегодняшними
   повторами. Между этапами показывается карточка перехода: рост освоения,
   заработанные XP и сигмы; в конце — итог занятия с похвалой.
5. **Ответ на задачу** — из занятия. Верный ответ поднимает mastery, XP и
   сигмы (счётчики в шапке занятия обновляются сразу); неверный заводит
   ошибку в полку и планирует повторы 1/3/7/30 дней.
6. **Отработка** `/practice/backlog/` — открытые ошибки и повторы на сегодня.
7. **Прогноз** `/forecast/` — текущий балл, потолок, ползунок темпа и дата
   экзамена.
8. **Домашки** `/homework/` — выданные куратором работы: прогресс «решено N из
   M», дедлайн, отметка «просрочено», ссылка на занятие по теме каждой задачи.
   Кнопка «Сдать как есть» отправляет работу до полного решения.
9. **Задание дня** `/daily/` — одна задача на сегодня с наградой XP; отвечать
   можно прямо на странице. Сверху — прогресс дня, текущая серия и остаток
   времени до полуночи, сбоку — неделя серии семью ячейками. После верного
   ответа страница показывает «Решено сегодня» и не даёт решить второй раз.
10. **Магазин** `/shop/` — баланс в сигмах (внутренняя валюта, жетон с Σ из
    знака). Витрина — карточки с иконкой, ярлыком и ценой, сверху баланс и
    запас заморозок, над сеткой фильтры по разделам. Косметика (аватары,
    рамки, четыре темы оформления) надевается, снимается кнопкой «Снять» и
    сбрасывается целиком кнопкой «Базовое оформление»; расходники
    (заморозка серии, ускорители опыта) покупаются повторно и срабатывают в
    момент покупки. Если сигм не хватает, карточка пишет, сколько именно.
10а. **Арена** `/arena/` — друзья и партии. Позвать в друзья по логину,
    принять встречную заявку, создать партию: режим, соперник (бот с уровнем
    1–5 или друг), прототип задания или случайный набор. Кнопка «Случайный
    соперник» ставит в очередь подбора: сначала ищется равный по рейтингу,
    окно расширяется каждые 10 секунд ожидания; через минуту предлагается бот
    своего уровня. В шапке партии — карточки обоих игроков: аватар с надетой
    рамкой, имя и счёт; счёт соперника обновляется по ходу игры, ответы
    остаются скрытыми до конца. После партии открывается разбор — свой ответ и
    правильный по каждому вопросу.

    Режимы проверяются по отдельности:

    - **нарешивание** — правило «кто быстрее решит набор» (5, 8, 12 или 16
      задач на выбор) или «кто больше решит за 2/3/5 минут». Во втором варианте в шапке идёт обратный отсчёт,
      а ответ после сигнала не принимается («Время партии вышло»);
    - **квиз** — вопрос по теории с четырьмя вариантами, общий для обоих.
      Первый верный клик забирает очки, промах закрывает вопрос для
      ошибившегося, но не для соперника; если не успел никто, вопрос сгорает
      по таймеру в 30 секунд;
    - **своя игра** — доска из пяти тем с ценами 100–500. Клетки выбирает тот,
      чей ход; верный ответ приносит цену и оставляет ход. Неверный списывает
      цену и отдаёт клетку сопернику вместе с ответом («Вы ответили «…» —
      неверно»): у перехвата свои тридцать секунд. Если ошиблись оба, цену
      теряют оба, клетка сгорает, а выбирать дальше будет тот, кто отвечал
      вторым. Молчание до конца таймера очков не стоит. Под доской — журнал
      разыгранных клеток с ответами обеих сторон. Счёт может уйти в минус —
      это правило, а не сбой.

    **Начало партии.** Партия не начинается, пока её не открыли оба игрока:
    до этого на экране висит ожидание («Ждём соперника за столом»), таймер
    стоит, вопросы закрыты. Проверяется так: создайте партию с другом, примите
    вызов вторым аккаунтом и убедитесь, что игра пошла только после того, как
    экран открыли оба. Создатель может снять ожидание кнопкой «Отменить
    партию»; забытое ожидание снимается само через пять минут. С ботом
    ожидания не видно — он за столом с самого начала.

    **Конец партии.** Партия закрывается, как только исход решён: если
    догнать соперника больше нечем, итог показывается сразу, не дожидаясь
    оставшихся вопросов. Проверяется быстрее всего с ботом первого уровня —
    достаточно решить несколько задач подряд. К закрытой партии нельзя
    присоединиться, ходы в ней отклоняются.

    **Выход.** Кнопка «Выйти из партии» на экране партии — это поражение, а не
    пауза: победа достаётся сопернику независимо от счёта. То же самое
    происходит с закрытой вкладкой: игрок, который молчит дольше минуты,
    считается ушедшим (в партии с ботом это не проверяется — там никто никого
    не ждёт).

    **Сложность бота** выбирается ползунком в любом режиме и используется как
    для прямой игры с ботом, так и для запасного бота, если живой соперник в
    очереди не нашёлся.

    Банк вопросов по теории раскладывается командой
    `.venv\Scripts\python.exe manage.py load_theory_bank` (и сам собой — в
    `seed_demo`). Без него квиз и «своя игра» честно откажутся начинаться.
10б. **Лига** `/leagues/` — месячное соревнование по опыту. По умолчанию
    выключено: на экране приглашение и объяснение, ничего не считается.
    Кнопка «Участвовать» сажает ученика в когорту своей лиги (Дельта →
    Гамма → Омега → Бетта → Альфа → Сигма), после чего опыт за уроки, задачи и
    повторы идёт в зачёт сезона. В таблице двадцать мест; свободные держат
    боты — они всегда ниже самого слабого живого участника и уступают место
    новому ученику. Зелёная граница после десятого места — зона повышения,
    у топ-5 подписана награда в сигмах. Кнопка «Выйти из лиги» возвращает
    экран к приглашению, место занимает бот, опыт остаётся.

    Итоги подводятся задачей `rotate_leagues` (celery beat, ежедневно в 00:10):
    сезон закрывается, топ-10 переходят выше, топ-5 получают сигмы, первое
    место в Бетте и выше — заморозки, ускоритель или золотую рамку и трофей в
    списке достижений. Проверить закрытие вручную:
    `.venv\Scripts\python.exe manage.py shell -c "from apps.gamification.leagues import close_season, current_season; print(close_season(current_season()))"`.

10в. **Структура экзамена.** В админке (`Exams → Exam profiles`) активный
    профиль — 2027 год: 20 заданий, максимум 33 первичных балла, часть 1 —
    задания 1–13, часть 2 — 14–20. На экране прогноза шкала первичных баллов
    показывает «из 33», а под ней — предупреждение о предварительной шкале
    перевода (пока официальной таблицы на 33 балла нет). Разложить структуру
    заново: `.venv\Scripts\python.exe manage.py load_exam_blueprint --dry-run`,
    затем без флага.

10г. **Косметика.** В магазине карточки аватаров и рамок показывают саму
    вещь, а не значок слота; у анимированных стоит ярлык «анимированный».
    «Примерить» подставляет вещь в значок в рельсе и отменяется кнопкой в
    полосе примерки. После надевания анимированной рамки движение видно только
    в своём значке в рельсе: в списках и таблицах анимация выключена, а при
    системной настройке «меньше движения» — везде. У нового ученика сразу есть
    четыре бесплатных аватара, один надет.

10д. **Лестница лиг и награды.** На `/leagues/` видна только своя лига и
    пройденные: выше — силуэты со знаком вопроса. В блоке наград сезона
    указано, что получают первые три места именно в этой лиге (в Дельте —
    заморозки серии, в Сигме — рамка чемпиона), а список «Награды» показывает
    полученные с жетоном места.

10е. **Рычаги прогноза.** На `/forecast/` ползунок нагрузки и дата экзамена
    двигают потолок и линейку. Когда времени хватает на весь материал, под
    рычагами появляется объяснение — иначе кажется, что ползунок сломан.
    Кнопка «Заниматься по этому сценарию» сохраняет нагрузку и дату и
    перестраивает план: после неё `/schedule/` показывает новый порядок.

10ж. **Нагрузка и расписание.** На `/schedule/` под заголовком месяца видно,
    сколько тем не помещается до экзамена при текущей нагрузке (если такие
    есть) и ссылка на прогноз. Поднимите нагрузку рычагом и нажмите
    «Заниматься по этому сценарию» — число непомещающихся тем уменьшится,
    а календарь перестроится.

10з. **Расходники магазина.** В категории «Ускорители» шесть позиций:
    заморозка серии поштучно, наборы ×5 и ×10 (на 10 % и 20 % дешевле
    поштучных) и ускорители опыта +50 % на 12, 24 и 48 часов — те же, что
    выдаёт лига за призовые места.

10и. **Совет по нагрузке.** На `/forecast/` под рычагами написано, сколько
    часов в неделю нужно, чтобы пройти план до экзамена, а на самом ползунке
    стоит отметка «нужно N ч». При смене даты экзамена совет и отметка
    пересчитываются.

11. **Тарифы** `/pricing/` — прайс, скидки, докупки (проверка эксперта и
    пакет подсказок наставника) и способы оплаты. Страница открыта без
    входа: цену смотрят родители до регистрации ученика.
12. **Пробник** `/mocks/` → «начать» → `/mocks/run/<id>/`. Часть 1 проверяется
    сразу, часть 2 уходит эксперту. Прикладывать решения второй части
    необязательно: пропущенная задача получает ноль, как на экзамене, и
    пробник закрывается, не дожидаясь работ, которых нет.

Проверка API той же ролью (вход по сессии уже есть в браузере):

```text
GET  /api/homework/                       домашки с прогрессом и дедлайном
POST /api/homework/<id>/submit/           сдать домашку
GET  /api/daily/                          задание дня и решено/нет
GET  /api/lessons/<node_id>/stages/       состояние трёх этапов занятия
POST /api/lessons/<node_id>/stages/       отметить материал просмотренным
GET  /api/wallet/                         баланс и последние начисления
GET  /api/shop/                           витрина с отметками куплено/надето
POST /api/shop/items/<id>/buy/            покупка
POST /api/shop/items/<id>/equip/          надеть (в слоте один предмет)
GET  /api/forecast/                       интервал, разбор по заданиям, покрытие профиля
GET  /api/gamification/                   XP, уровень, стрик, квесты
```

Что должно сойтись:

- домашка закрывается сама, когда решены все её задачи, и платит один раз;
- задание дня засчитывается только верной попыткой того же дня;
- покупка без баллов даёт понятную ошибку 400, а не 500;
- в `/api/forecast/` сумма `tasks[].expected_points` равна ожидаемому
  первичному баллу, а `exam_profile_coverage` показывает 19 размеченных
  заданий из 19 (`unmapped_numbers` пустой);
- под ответом на задачу появляется строка прогресса по теме: mastery,
  «решено N из M» и отметка о закрытом пункте плана;
- на `/map/` карта открывается графом: кластеры, рёбра-зависимости, кольцо
  освоения. Клик по теме оставляет только цепочку её пререквизитов, кнопка
  «Список тем» возвращает прежние карточки;
- шкала прогноза в кабинете и на `/forecast/` считается в первичных баллах:
  цель и потолок подписаны на той же оси, тестовые даны переводом. При
  низком и при максимальном балле подписи расходятся по рядам и прижимаются
  к краю — проверьте на ученике без решённых задач;
- точка урока на дорожке закрывается, когда решены все задачи темы, а не
  когда тема освоена до порога: это разные критерии и разные точки;
- папка навыков нигде не ведёт себя как навык: её нет ни в плане, ни на
  дорожке, ни в прогнозе, ни в списке «нечем закрыть» у методиста, а процент
  у неё считается по детям — средним или по самому слабому, как задано в
  карточке узла;
- поддерживающая связь не закрывает тему: узел с одной только такой связью
  остаётся доступным, а сама связь показывается отдельно от условий открытия;
- вердикт эксперта виден ученику в разделе «Отработка»: балл, комментарий и
  форма повторной загрузки, если работу вернули на доработку;
- ответ на задачу возвращает `rewards`: сколько дали XP и сигм и как
  изменилось освоение темы — по этим числам занятие рисует анимацию
  перехода между этапами;
- `/lesson/<node_id>/summary.md` отдаёт конспект файлом и только ученику;
- партия арены не двигает освоение тем и не заводит ошибки на полку: ответы
  видны в журнале попыток с контекстом `arena`, но скорость под таймером —
  не свидетельство понимания. Награда даётся за первые пять партий в день;
- результат бота разыгран при создании партии: он не зависит от того, как
  играет человек, и воспроизводится по номеру партии;
- рейтинг меняется только в случайных партиях двух людей: вызов друга и игра
  с ботом на него не влияют. Стартовое значение берётся из прогноза балла.

## 4. Родитель (`parent`)

Кабинет `/parent/`.

1. Недельный отчёт по блокам:
   - **Факт недели** — закрытые пункты плана (по дате закрытия), решённые
     задачи, пройденные пробники;
   - **Прогресс по программе** — сколько тем освоено из всех, сколько в
     работе и подзабылось, среднее освоение, закрытые пункты плана за всё
     время и верно решённые задачи недели;
   - **Текущая траектория** — выбранный сценарий (78+/84+/90+), его
     диапазон баллов, требуемые часы против заявленных учеником, отметка
     «темп держится/ниже плана», дата экзамена и последний переход с
     причинами и списком «что вернуть»;
   - **Динамика** — прогноз по последним замерам; если ночная джоба не
     запускалась, замер снимается при открытии отчёта, поэтому прочерка
     быть не должно;
   - риски, слабые темы, распределение типов ошибок, следующий шаг.
2. Лог ИИ-наставника по своему ребёнку — `GET /api/parent/ai-log/`.
3. Отчёт через API — `GET /api/parent/report/`.

Что проверить на границах доступа: родитель видит только своего ребёнка.
Запрос отчёта с чужим `?student=<id>` должен вернуть 404, а не данные.
Панель `/panel/` под родителем — 403 (проверено).

## 5. Эксперт (`expert`)

Кабинет `/expert/`.

1. Очередь работ второй части: сортировка по дедлайну SLA, просроченные
   помечены. В демо одна работа уже просрочена — так видно оформление.
2. Карточка проверки `/expert/review/<id>/`: работа ученика, условие задачи,
   критерии, типы ошибок, связанные узлы.
3. Вердикт: баллы по критериям, комментарий, при необходимости —
   «на доработку». После вердикта пересчитываются mastery, полка ошибок и,
   если это работа из пробника, итог пробника с калибровкой прогноза.
4. Файл работы открывается по ссылке из карточки
   (`/api/expert-reviews/<id>/file/`), а не из публичного каталога.

Проверка приватности. Демо-работа принадлежит ученику `student`, поэтому под
ним она открывается — это правильно. Изоляцию проверяйте вторым учеником:

```powershell
python manage.py shell -c "from apps.accounts.models import StudentProfile, User; u,_=User.objects.get_or_create(username='student2', defaults={'role':'student'}); u.set_password('demo12345'); u.save(); StudentProfile.objects.get_or_create(user=u)"
```

Войдите как `student2` и откройте `/api/expert-reviews/1/file/` — ожидается
**404**, а не 403 и не сам файл. Проверено: под владельцем 200, под чужим
учеником 404. То же правило действует для родителя чужого ребёнка.

Проверка прав: `/panel/` под экспертом должен отдать 403 — панель ведёт
методист.

## 6. Методист (`methodist`)

Две точки входа: обзорный кабинет `/methodist/` и рабочая панель `/panel/`.

Кабинет `/methodist/` — «дыры контента»: задачи без эталонного разбора, уроки
без теории и видео, узлы без задач, граф по кластерам с порогами рёбер.
Отсюда же кнопки в рабочую панель, Django-админку и на страницу тарифов; те
же переходы есть в левом рельсе.

Панель `/panel/` — редактирование по разделам:

| Раздел | Что проверить |
| --- | --- |
| Уроки | создать урок, добавить видео, «Опубликовать». Пустой урок опубликовать нельзя — это ожидаемая ошибка |
| Задачи | «Новая версия» после правки условия; старые попытки остаются на прежней версии (раздел «Версии задач») |
| Домашки | создать, добавить задачи, «Выдать» с ID группы |
| Задания дня | одна задача на дату с наградой |
| Ученики | «Начислить баллы», «Отключить»/«Включить» |
| Приглашения | создать код; ссылка `/invite/<код>/` открывает регистрацию с уже заполненным кодом |
| Способы оплаты | добавить способ; пустой `provider_key` = «оплата вручную», такой способ помечается на витрине |
| Скидки и акции | процент или фиксированная сумма, срок, лимит применений, ограничение по кодам тарифов; счётчик применений правкой не подделать |
| Докупки (апселлы) | разовые опции сверх тарифа: проверка эксперта и пакет подсказок; в списке видна цена за единицу |
| Товары магазина | у косметики есть код (`owl`, `dark`, `coordinates`…) — по нему интерфейс рисует аватар, рамку и тему; у расходника — эффект, значение и срок |
| Граф | узлы, часы на узел, зависимости. Попытка создать цикл отклоняется с сообщением |
| Профиль экзамена | задания, баллы, сложность, связь с узлами |
| Прогноз против факта | пары «прогноз — факт» по пробникам |
| Магазин | категории, товары, кошельки, реестр (только чтение), инвентарь |
| Тарифы | «Новая цена» создаёт новую версию, старая уходит в архив. Правкой строки цена не меняется — только название, описание и активность |
| Платежи | «Вернуть деньги» снимает подписку |

Видео Kinescope: в поле `video_url` достаточно идентификатора ролика —
embed-ссылку собирает модель. Проверить можно на уроке `frac-powers`.

Django-админка `/admin/` остаётся доступной для точечных правок и журналов.

Прод-настройки (в dev-режиме проверка бесполезна — нужны боевые значения):

```powershell
$env:DJANGO_DEBUG="0"
$env:DJANGO_SECRET_KEY="<строка не короче 50 символов с разными символами>"
$env:DJANGO_ALLOWED_HOSTS="matemacia.ru"
```

С `DEBUG=0` и ключом разработки процесс намеренно не поднимется — это
fail-fast из `config/security.py`.

Эксплуатация:

```powershell
curl http://127.0.0.1:8000/healthz   # процесс жив
curl http://127.0.0.1:8000/readyz    # база и кеш отвечают
```

`/readyz` возвращает 503, если отвалилась база или кеш — на него вешается
проверка балансировщика. Лимиты частоты настраиваются переменными
`THROTTLE_ATTEMPT`, `THROTTLE_HINT`, `THROTTLE_PURCHASE`, `THROTTLE_UPLOAD`,
`THROTTLE_ARENA_STATE`, `THROTTLE_ARENA_MOVE`,
`LOGIN_MAX_ATTEMPTS`; в проде нужен `REDIS_URL`, иначе счётчик у каждого
воркера свой. С `DJANGO_DEBUG=0` процесс не поднимется на SQLite.

Пошаговая проверка второй части:

У задачи может быть эталонный путь (`/panel/` → «Пути решения») с
упорядоченными шагами («Шаги путей»). Если путь есть, форма эксперта показывает
чек-лист: по каждому шагу — «Верно», «С ошибкой», «Не делал».

Что должно сойтись: верно выполненные шаги поднимают свои навыки, ошибочный —
понижает свой и заводит ошибку на полку с типом по этапу шага, а «Не делал»
не меняет ничего. Ученик в разделе «Отработка» видит блок «Что не сошлось» —
список обязательных шагов, которые эксперт не отметил верными. Если пути у
задачи нет, вердикт работает по-старому, через темы задачи.

Ответы-множества (задание 13):

У задачи есть тип ответа (`answer_type`) и эталон в разобранном виде
(`answer_spec`) — оба правятся в панели и в админке:

```json
{"families": ["pi/6 + 2*pi*k", "5*pi/6 + 2*pi*k"]}
{"roots": ["7*pi/6", "11*pi/6", "19*pi/6"]}
```

Проверяется множество точек, а не строка: порядок серий, буква параметра и
форма записи не важны, `π/4+πk/2` равно паре `π/4+πk`, `3π/4+πk`. Понимаются
π и «pi», знак ±, разделители «;», запятая и перенос строки.

Нечитаемая запись — это не «неверно»: занятие отвечает 422 с кодом
`answer_not_understood`, попытка не создаётся, ошибка на полку не идёт. На
пробнике и диагностике такой ответ засчитывается неверным (переспросить
некого). Эталон проверяется при сохранении задачи: опечатка в нём не доедет до
ученика.

Проверить вручную: задача с типом «Семейства корней», ответить «π/6+2πn» при
эталоне `pi/6 + 2*pi*k` — верно; «π/6+2πk +» — «не понял запись», освоение не
меняется.

Предметная разметка (навыки и связи задания 13):

```powershell
python manage.py load_markup --dry-run   # показать разницу, ничего не менять
python manage.py load_markup             # применить
python manage.py load_markup --prune     # убрать узлы, которых нет в книге
```

Данные лежат в `apps/knowledge/markup/`, загрузка идемпотентна по коду навыка:
повтор ничего не меняет. Приезжает 66 узлов (61 навык и 5 папок) и 60 связей,
из них 33 — ворота. Часы и вес узлов команда не трогает: их правит методист в
панели. Узел, исчезнувший из книги, показывается как лишний и удаляется только
с `--prune`, да и то лишь если на него не ссылаются задачи и история учеников.

Проверить: после загрузки в `/panel/` (раздел «Узлы графа») видно 66 записей, а
на `/methodist/` те же навыки попадают в «нечем закрыть» — задач к ним пока нет,
и это правильный сигнал, а не ошибка.

Второй фактор сотрудников:

```powershell
$env:TWO_FACTOR_ENFORCED = "1"                 # с DJANGO_DEBUG=0 включён сам
$env:TWO_FACTOR_REQUIRED_ROLES = "methodist,expert"
.venv\Scripts\python.exe manage.py reset_two_factor <логин>   # потерян телефон
```

Методист, эксперт, `is_staff` и суперпользователь после пароля попадают на
настройку фактора (TOTP: ключ, приложение-аутентификатор, код). Проверка стоит
в middleware, поэтому `/admin/` закрыт так же, как панель. Код нельзя ввести
дважды, после пяти неверных — блокировка на 15 минут. Резервные коды
показываются один раз и хранятся отпечатками. Ученик и родитель фактор не
проходят.

Доступ к платной части:

```powershell
$env:BILLING_ENFORCED = "1"   # включить гейт
$env:TRIAL_DAYS = "7"         # пробный период от даты регистрации
$env:FREE_FEATURES = "practice"  # что остаётся бесплатным
```

Гейт закрывает занятия (`lessons`), отработку (`practice`), пробники (`mocks`),
проверку эксперта (`expert_review`) и подсказки наставника (`ai_hints`).
Страница уводит на `/pricing/?locked=<возможность>`, API отвечает 403 с
`code=subscription_required`. Сотрудники и родители под гейт не попадают.
Проверить вручную: включить `BILLING_ENFORCED`, зайти учеником без подписки и
открыть `/lesson/<id>/` — должна открыться витрина с объяснением.

Колбэк эквайринга: `POST /api/billing/webhook/`, подпись тела HMAC-SHA256 на
`BILLING_WEBHOOK_SECRET` в заголовке `X-Signature`. Без секрета или с чужой
подписью запрос получает 403 и ничего не меняет; повторная доставка не
продлевает подписку дважды. С `DJANGO_DEBUG=0` и небоевым провайдером процесс
не поднимется без секрета.

Видео занятий:

```powershell
$env:KINESCOPE_SIGNING_KEY = "..."   # ключ подписи приватных роликов
$env:KINESCOPE_KEY_ID = "..."        # уходит в заголовок токена как kid
$env:VIDEO_LINK_TTL_SECONDS = "600"  # сколько живёт выданная ссылка
$env:VIDEO_ALLOWED_HOSTS = "kinescope.io,rutube.ru"
```

Ссылка на плеер не рендерится в HTML: страница несёт только адрес выдачи
`/api/lessons/<id>/playback/`, а ссылку отдаёт запрос — он проходит через гейт
подписки, пишется в лог `matemacia.integrations` и живёт `VIDEO_LINK_TTL_SECONDS`.
Проверить: открыть занятие, посмотреть исходник — домена видеохостинга в нём
быть не должно; нажать «Смотреть занятие» — плеер появляется.

Без `KINESCOPE_SIGNING_KEY` ссылки остаются публичными, и ответ честно говорит
об этом полем `is_private: false`. Подключение приватных роликов — это ключ в
переменных и, если контракт хостинга отличается, имена полей токена
(`KINESCOPE_TOKEN_PARAM`, `KINESCOPE_TOKEN_CLAIMS`); код менять не нужно.
Хост видео проверяется при сохранении урока — и в Django-админке, и в панели.
В личном кабинете плеер получает `referrerpolicy="strict-origin-when-cross-origin"`:
общая политика сайта срезает Referer, а домен-whitelist на стороне хостинга
без него не работает.

Выкладка в прод, откат, бэкапы и репетиция восстановления описаны отдельно —
`docs/deploy.md`. Манифест лежит в `infra/production/`: образ приложения,
compose с вебом, воркером, расписанием и nginx, пример окружения, скрипты
снятия и разворачивания копии. Локальная разработка не затронута: `gunicorn`
стоит в отдельном `requirements-production.txt` и на Windows не ставится.

Система навыков агентов:

```powershell
.\scripts\install-skills.ps1          # 127 скиллов в .claude\skills и .agents\skills
.\scripts\validate-skills.ps1 -Strict # 50 собственных скиллов
.\scripts\skills-ci.ps1               # 12 проверок целостности, ожидается PASS
```

Те же проверки идут в CI (`.github/workflows/ci.yml`) на `windows-latest`:
job `tests` гоняет `scripts\test.ps1`, job `skills` — валидатор скиллов и
`skills-ci.ps1` с `-SkipInstallChecks` (установленные каталоги не коммитятся).

## 9. Частые проблемы

**`ParserError` при запуске `.ps1` с кириллицей.** Windows PowerShell 5.1
читает файлы без BOM в системной кодировке. Скрипты репозитория сохранены в
UTF-8 **с BOM** — при правке сохраняйте BOM.

**`makemigrations` зависает с вопросом про переименование поля.** Запускайте
с `--noinput`: вопрос интерактивный и в неинтерактивной среде роняет команду.

**Урок не виден ученику.** Он в черновике: опубликуйте его в панели.

**Прогноз занижен.** Часть заданий профиля экзамена не размечена узлами и даёт
ноль. Смотрите `exam_profile_coverage` в `/api/forecast/` и раздел «Задания
экзамена» в панели.

**Интервал прогноза широкий.** Так и должно быть, пока не проверен ни один
пробник: разброс берётся из `FORECAST_PRIOR_SIGMA_PRIMARY`, дальше считается
по фактическим ошибкам.

**403 на `/panel/`.** Панель открывает роль методиста или суперпользователь;
флага `is_staff` недостаточно.

**Начать с чистого листа:**

```powershell
Remove-Item db.sqlite3, private-media -Recurse -Force -ErrorAction SilentlyContinue
python manage.py migrate
python manage.py seed_demo
```
