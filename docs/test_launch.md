# Локальный запуск и проверка функционала по ролям

Инструкция от чистого клона до пройденных вручную сценариев каждой роли.
Команды — для Windows PowerShell (основная среда разработки); для bash
отличается только активация окружения и разделители путей.

---

## 1. Подготовка

| Компонент | Зачем | Обязателен |
| --- | --- | --- |
| Python 3.10+ (проверено на 3.13) | сам сервис | да |
| Git | клон и история | да |
| Redis | брокер Celery для фоновых задач | нет — см. §7 |
| PostgreSQL | боевая БД; локально хватает SQLite | нет |

```powershell
git clone <адрес-репозитория> Mathemation
cd Mathemation
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell блокирует `Activate.ps1`, один раз разрешите скрипты:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

## 2. База и демо-данные

```powershell
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

`seed_demo` идемпотентна. Она создаёт: 16 узлов графа с зависимостями,
16 опубликованных уроков (два с видео), 18 задач, профиль экзамена 2027
из 19 заданий, входную диагностику, пробник, домашку на трёх задачах,
задание дня, пять предметов магазина, одну работу второй части в очереди
эксперта и четырёх пользователей.

| Логин | Роль | Что открыто |
| --- | --- | --- |
| `student` | ученик | кабинет `/` и все ученические страницы |
| `parent` | родитель | `/parent/` по своему ребёнку |
| `expert` | эксперт | `/expert/` — очередь проверки второй части |
| `methodist` | методист | `/methodist/` и панель `/panel/` |

Пароль у всех — `demo12345`. Вход — `http://127.0.0.1:8000/accounts/login/`;
любая закрытая страница сама перебросит туда с параметром `next`.

## 3. Ученик (`student`)

Кабинет `/`. Проверяйте по порядку — каждый шаг опирается на предыдущий.

1. **Дашборд.** Прогноз показан интервалом, рядом — потолок при текущем темпе,
   стрик, уровень и XP, квесты недели, план на сегодня, отработка.
2. **Карта навыков** `/map/` — состояния узлов: закрыто, можно начинать,
   в процессе, освоено, подзабылось. Закрытый узел показывает, какого
   пререквизита и до какого процента не хватает.
3. **Дорожка** `/track/` — точки уроков и практики по темам, текущая помечена.
4. **Урок** `/lesson/<node_id>/` — видео (у `frac-powers` и `linear-quadratic`),
   теория, задачи, панель ИИ-наставника.
5. **Ответ на задачу** — из урока. Верный ответ поднимает mastery, XP и монеты;
   неверный заводит ошибку в полку и планирует повторы 1/3/7/30 дней.
6. **Отработка** `/practice/backlog/` — открытые ошибки и повторы на сегодня.
7. **Прогноз** `/forecast/` — текущий балл, потолок, ползунок темпа и дата
   экзамена.
8. **Пробник** `/mocks/` → «начать» → `/mocks/run/<id>/`. Часть 1 проверяется
   сразу, часть 2 уходит эксперту.

Проверка API той же ролью (вход по сессии уже есть в браузере):

```text
GET  /api/homework/                       домашки с прогрессом и дедлайном
POST /api/homework/<id>/submit/           сдать домашку
GET  /api/daily/                          задание дня и решено/нет
GET  /api/wallet/                         баланс и последние начисления
GET  /api/shop/                           витрина с отметками куплено/надето
POST /api/shop/items/<id>/buy/            покупка
POST /api/shop/items/<id>/equip/          надеть (в слоте один предмет)
GET  /api/forecast/                       интервал, разбор по заданиям, покрытие профиля
GET  /api/gamification/                   XP, уровень, стрик, квесты
```

Что должно сойтись:

- домашка закрывается сама, когда решены все её задачи, и платит один раз;
- задание дня засчитывается только верной попыткой того же дня;
- покупка без баллов даёт понятную ошибку 400, а не 500;
- в `/api/forecast/` сумма `tasks[].expected_points` равна ожидаемому
  первичному баллу, а `exam_profile_coverage` показывает 13 размеченных
  заданий из 19 — остальные честно дают ноль.

## 4. Родитель (`parent`)

Кабинет `/parent/`.

1. Недельный отчёт: факт недели, динамика прогноза, риски, слабые темы,
   распределение типов ошибок, следующий шаг.
2. Лог ИИ-наставника по своему ребёнку — `GET /api/parent/ai-log/`.
3. Отчёт через API — `GET /api/parent/report/`.

Что проверить на границах доступа: родитель видит только своего ребёнка.
Запрос отчёта с чужим `?student=<id>` должен вернуть 404, а не данные.
Панель `/panel/` под родителем — 403 (проверено).

## 5. Эксперт (`expert`)

Кабинет `/expert/`.

1. Очередь работ второй части: сортировка по дедлайну SLA, просроченные
   помечены. В демо одна работа уже просрочена — так видно оформление.
2. Карточка проверки `/expert/review/<id>/`: работа ученика, условие задачи,
   критерии, типы ошибок, связанные узлы.
3. Вердикт: баллы по критериям, комментарий, при необходимости —
   «на доработку». После вердикта пересчитываются mastery, полка ошибок и,
   если это работа из пробника, итог пробника с калибровкой прогноза.
4. Файл работы открывается по ссылке из карточки
   (`/api/expert-reviews/<id>/file/`), а не из публичного каталога.

Проверка приватности. Демо-работа принадлежит ученику `student`, поэтому под
ним она открывается — это правильно. Изоляцию проверяйте вторым учеником:

```powershell
python manage.py shell -c "from apps.accounts.models import StudentProfile, User; u,_=User.objects.get_or_create(username='student2', defaults={'role':'student'}); u.set_password('demo12345'); u.save(); StudentProfile.objects.get_or_create(user=u)"
```

Войдите как `student2` и откройте `/api/expert-reviews/1/file/` — ожидается
**404**, а не 403 и не сам файл. Проверено: под владельцем 200, под чужим
учеником 404. То же правило действует для родителя чужого ребёнка.

Проверка прав: `/panel/` под экспертом должен отдать 403 — панель ведёт
методист.

## 6. Методист (`methodist`)

Две точки входа: обзорный кабинет `/methodist/` и рабочая панель `/panel/`.

Кабинет `/methodist/` — «дыры контента»: задачи без эталонного разбора, уроки
без теории и видео, узлы без задач, граф по кластерам с порогами рёбер.

Панель `/panel/` — редактирование по разделам:

| Раздел | Что проверить |
| --- | --- |
| Уроки | создать урок, добавить видео, «Опубликовать». Пустой урок опубликовать нельзя — это ожидаемая ошибка |
| Задачи | «Новая версия» после правки условия; старые попытки остаются на прежней версии (раздел «Версии задач») |
| Домашки | создать, добавить задачи, «Выдать» с ID группы |
| Задания дня | одна задача на дату с наградой |
| Ученики | «Начислить баллы», «Отключить»/«Включить» |
| Приглашения | создать код; по нему человек регистрируется сам |
| Граф | узлы, часы на узел, зависимости. Попытка создать цикл отклоняется с сообщением |
| Профиль экзамена | задания, баллы, сложность, связь с узлами |
| Прогноз против факта | пары «прогноз — факт» по пробникам |
| Магазин | категории, товары, кошельки, реестр (только чтение), инвентарь |
| Тарифы | «Новая цена» создаёт новую версию, старая уходит в архив |
| Платежи | «Вернуть деньги» снимает подписку |

Видео Kinescope: в поле `video_url` достаточно идентификатора ролика —
embed-ссылку собирает модель. Проверить можно на уроке `frac-powers`.

Django-админка `/admin/` остаётся доступной для точечных правок и журналов.

```powershell
python manage.py test apps config              # весь набор, сейчас 284 теста
```

Прод-настройки (в dev-режиме проверка бесполезна — нужны боевые значения):

```powershell
$env:DJANGO_DEBUG="0"
$env:DJANGO_SECRET_KEY="<строка не короче 50 символов с разными символами>"
$env:DJANGO_ALLOWED_HOSTS="matemacia.ru"
```

fail-fast из `config/security.py`.

## 9. Частые проблемы

**`ParserError` при запуске `.ps1` с кириллицей.** Windows PowerShell 5.1
читает файлы без BOM в системной кодировке. Скрипты репозитория сохранены в
UTF-8 **с BOM** — при правке сохраняйте BOM.

**`makemigrations` зависает с вопросом про переименование поля.** Запускайте
с `--noinput`: вопрос интерактивный и в неинтерактивной среде роняет команду.

**Урок не виден ученику.** Он в черновике: опубликуйте его в панели.

**Прогноз занижен.** Часть заданий профиля экзамена не размечена узлами и даёт
ноль. Смотрите `exam_profile_coverage` в `/api/forecast/` и раздел «Задания
экзамена» в панели.

**Интервал прогноза широкий.** Так и должно быть, пока не проверен ни один
пробник: разброс берётся из `FORECAST_PRIOR_SIGMA_PRIMARY`, дальше считается
по фактическим ошибкам.

**403 на `/panel/`.** Панель открывает роль методиста или суперпользователь;
флага `is_staff` недостаточно.

**Начать с чистого листа:**

```powershell
Remove-Item db.sqlite3, private-media -Recurse -Force -ErrorAction SilentlyContinue
python manage.py migrate
python manage.py seed_demo
```
