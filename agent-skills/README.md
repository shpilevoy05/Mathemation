# Управление скиллами Матемации

`agent-skills/` — источник правды для скиллов, доступных агентам в этом репозитории. Установочные каталоги `.claude/skills/` и `.agents/skills/` являются производными копиями и обновляются скриптом установки.

## Структура каталогов

```text
agent-skills/
├── matemacia/                 # собственные предметные скиллы
│   └── <skill>/SKILL.md
├── vendor/                    # проверенные снимки внешних репозиториев
│   └── <vendor>/<skill>/SKILL.md
├── README.md                  # правила управления
└── golden-tasks.md            # регрессионный acceptance suite
skills.lock.yaml               # репозитории, полные SHA и дата ревью vendor-снимков
scripts/audit-skills.ps1       # аудит опасных конструкций
scripts/install-skills.ps1     # установка в каталоги обнаружения агентов
scripts/check-skills-integrity.py
```

Содержимое `agent-skills/vendor/` не редактируется локально. Любое изменение vendor-скилла выполняется только обновлением снимка из зафиксированного upstream-коммита.

## Обновление vendor-скиллов

1. Клонировать соответствующий upstream-репозиторий во временный каталог и перейти на конкретный commit.
2. Скопировать нужные каталоги скиллов в `agent-skills/vendor/<vendor>/`, не смешивая изменения с собственными скиллами.
3. Запустить `powershell -File scripts/audit-skills.ps1 -Path agent-skills\vendor\<vendor>`.
4. Разобрать все результаты `REVIEW` вручную. Результат `BLOCK` запрещает обновление до устранения причины.
5. Сверить diff содержимого с upstream и записать полный 40-символьный SHA в `skills.lock.yaml`; заполнить `reviewed_at`.
6. Запустить `.\venv\Scripts\python.exe scripts\check-skills-integrity.py`.
7. Установить проверенный набор командой `powershell -File scripts/install-skills.ps1`.
8. Повторить проверку целостности и убедиться, что наборы имён в `.claude/skills/` и `.agents/skills/` совпадают.

Порядок обязателен: clone → audit → полный SHA в lock → install. Установка непроверенного снимка не допускается.

## Приоритет инструкций

При конфликте рекомендаций применяется четыре уровня, сверху вниз:

1. Инварианты продукта — `matemacia-product-invariants`.
2. Собственный предметный скилл Матемации для изменяемого домена.
3. Vendor best practices как справочные универсальные рекомендации.
4. Общие инженерные советы.

Поле `conflicts_with` в собственном `SKILL.md` отмечает известные зоны пересечения. Оно не отключает vendor-скилл, а фиксирует, что предметный контракт Матемации имеет приоритет.

## Версионирование собственных скиллов

Версия хранится в `metadata.version` по SemVer:

- patch — уточнение текста, примеров или формулировок без изменения требуемого поведения;
- minor — новое правило, новая проверка или расширение области активации при сохранении прежних контрактов;
- major — изменение продуктового инварианта или несовместимое изменение поведения агента.

Для major-изменения скилла с `metadata.criticality: high` новая версия и последствия обязательно указываются в соответствующем техническом решении. Каждое изменение обновляет `metadata.last_reviewed`, проходит аудит и релевантные задачи из `golden-tasks.md`.

## Человеческое подтверждение

Скиллы, связанные с deployment, миграциями, платежами или секретами, могут давать план, проверки и безопасные подготовительные шаги, но фактический запуск потенциально изменяющего внешнее состояние действия выполняется только после явного подтверждения человека. Это ограничение нельзя ослабить рекомендацией vendor-скилла или общим инженерным советом.

## Приёмка

Перед установкой или публикацией изменений:

```powershell
.\.venv\Scripts\python.exe scripts\check-skills-integrity.py
powershell -File scripts/audit-skills.ps1 -Path agent-skills\matemacia
```

Затем прогоняются затронутые карточки из `golden-tasks.md`, а протокол сохраняет выбранные скиллы, прочитанные файлы, проверки, инварианты и вмешательство человека.
