# Анти-паттерны структуры скиллов

## 1. Описание без условий применения

«Скилл про базу данных» не позволяет агенту решить, когда его брать. Описание
содержит объект («схема, миграции, индексы») и триггер («использовать при…»).

## 2. Negative cases одной фразой

«В остальных случаях не применять» не проверяется тестом. Нужны конкретные
запросы, на которых скилл активироваться не должен.

## 3. Всё в SKILL.md

Скилл на 800 строк читается целиком при каждой активации и вытесняет контекст
задачи. Примеры и разборы — в `references/`.

## 4. Скрипт вместо инструкции

`scripts/` существует для проверок, а не для того, чтобы агент запускал код на
каждый вопрос. Если задачу решает чтение файла, скрипт не нужен.

## 5. Абсолютные пути

Путь с буквой диска или домашним каталогом работает на одной машине и ломается
у всех остальных, включая CI.

## 6. Дублирование reference-блоков

Один и тот же чек-лист в `SKILL.md` и в `references/examples.md` расходится
через два месяца, и агент читает устаревшую копию.

## 7. Пустой раздел ради галочки

Заголовок «Критерии приёмки» без содержания хуже отсутствия раздела: валидатор
считает такой раздел отсутствующим, а автор считает работу сделанной.

## 8. valid как доказательство полезности

Валидная структура не означает, что агент выберет скилл в нужный момент.
Это измеряет `skill-routing-evaluation`.
