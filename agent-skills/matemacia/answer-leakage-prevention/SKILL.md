# Предотвращение утечки ответа

Запрещай наставнику называть финальный ответ прямо или эквивалентной записью.
Используй два независимых слоя: редакцию входа и проверку выхода.

## Редакция входа

- Никогда не клади `correct_answer` или `Assignment.correct_answer` в prompt.
- Применяй `_redact_answer` в `apps/ai_mentor/providers.py` ко всем контекстным блокам.
- Редактируй точное вхождение в statement, reference solution, question и history.
- Не передавай ответ в metadata, tool args, hidden JSON или provider logs.
- Не полагайся на обещание провайдера не использовать скрытое поле.
- Для части 2 не подменяй критерии готовым решением.

## Проверка выхода

- Используй `contains_final_answer` из `apps/ai_mentor/guardrails.py`.
- Сравнивай числовую эквивалентность через SymPy, а не только строки.
- Распознавай дробь, десятичную запись, корень, степень и эквивалентное выражение.
- Не считай числа, уже встречающиеся в условии, утечкой сами по себе.
- Не проверяй символический answer как числовой без надёжного контракта.
- Лови SymPy exceptions и не допускай падения запроса.

## Блокировка

- Добавляй `final_answer` в `failed_claims` при обнаружении утечки.
- Сохраняй исходный provider text как `AiHintMessage.is_blocked=True`.
- Не показывай этот текст ученику или родителю.
- Показывай нейтральный `GUARDRAIL_BLOCK_TEXT` и предлагай человека.
- Пиши событие `hint_blocked_by_guardrail`.
- Не помещай заблокированный текст в event payload.

## Границы

- Применяй выходной фильтр даже после безопасного RAG.
- Применяй его одинаково к LLM и mock/fallback providers.
- Не разрешай аналогичному примеру быть идентичной задачей с тем же ответом.
- Не раскрывай ответ после двух неудачных подсказок; эскалируй.
- Не ослабляй фильтр ради «полезности» ответа.

## Проверка

- Проверь точный ответ и численно эквивалентные формы.
- Проверь, что числа из условия не дают ложный блок.
- Проверь блок, событие и отсутствие видимого текста.
- Проверь, что заблокированный текст не попадает в следующий prompt или parent log.
