# Анти-паттерны CI-контроля

## 1. Правка lock-файла под состояние диска

Lock — источник истины, диск — производное. Обратное направление скрывает, что
установленное содержимое никто не аудировал.

## 2. Коммит каталогов установки

`.claude/skills` и `.agents/skills` восстанавливаются из lock. Коммит делает
два источника истины и гарантирует расхождение.

## 3. `SKIP` в релизном отчёте

Пропущенная проверка — не пройденная проверка. Релиз с `SKIP` по проверкам 5–6
означает, что состав навыков не подтверждён.

## 4. Отключение проверки ради срочного merge

Срочность лечится узким фиксом, а не отключением контроля. Отключённая
проверка не возвращается сама.

## 5. Недетерминированные проверки в CI

Обращение к сети или запуск агента в CI делает результат зависящим от внешних
условий. Прогоны агентов живут в `skill-acceptance-suite`, а в CI попадают уже
как записанные отчёты.

## 6. Один общий FAIL без причин

«Integrity failed» без перечня проблем заставляет воспроизводить локально.
Каждая проверка печатает конкретные строки.

## 7. Проверка только собственных скиллов

Vendor-каталог — основной источник риска. Проверки 1–4, 7 относятся именно
к нему.
