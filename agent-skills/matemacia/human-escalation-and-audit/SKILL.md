# Эскалация человеку и аудит

Считай эскалацию штатным безопасным исходом, а не ошибкой системы.
Работай с `AiHintSession` и `AiHintMessage` в `apps/ai_mentor/models.py`.

## Триггеры

- Эскалируй после `AI_MENTOR_MAX_HINTS` из `config/settings.py`.
- Эскалируй после ложного математического утверждения.
- Эскалируй после обнаружения финального ответа.
- Эскалируй, когда провайдер не уверен или reference solution отсутствует.
- Не выдавай дополнительную «последнюю» подсказку после лимита.
- Устанавливай `escalated_to_expert=True` на сессии.

## Сообщения

- Сохраняй заблокированный provider text с `is_blocked=True`.
- Сохраняй `failed_claims` и `unverified_claims` для методического аудита.
- Не показывай заблокированный текст ученику.
- Не показывай заблокированный текст родителю.
- Не включай его в следующий LLM-контекст.
- Показывай безопасное сообщение с предложением живого преподавателя.
- Используй нейтральный тон без обвинения ученика.

## Эксперт и методист

- Показывай эскалации эксперту в `/expert/` через `expert_queue_context`.
- Ограничивай очередь последними релевантными сессиями и role permissions.
- Давай методисту аудит заблокированных текстов для улучшения корпуса и промпта.
- Не позволяй методисту превращать заблокированный ответ в эталон без верификации.
- Связывай сессию с assignment и knowledge node для разбора причины.
- Не раскрывай лишние ПДн в очереди.

## События

- Логируй блок как `hint_blocked_by_guardrail`.
- Логируй выданную подсказку как `hint_issued`.
- Передавай только assignment id, hint index и типы failed claims.
- Не передавай текст вопроса или ответа в payload.
- Не изменяй историческое событие после аудита.

## Проверка

- Проверь лимит, SymPy-блок, утечку ответа и provider failure.
- Проверь видимость для ученика, родителя, эксперта и методиста.
- Проверь исключение blocked message из LLM history.
- Проверь audit fields и безопасный event payload.
