# Анти-паттерны приёмки

## 1. Приёмка «по факту установки»

«115 навыков установлены — значит работает». Установка не проверяет ни выбор
скиллов, ни соблюдение инвариантов.

## 2. Сокращённый набор golden tasks

18 задач — минимум, а не рекомендация. Сокращение до «быстрых» задач убирает
именно те проверки, где ломаются продуктовые инварианты.

## 3. Прогон на одном агенте

Расхождение Claude Code и Codex — отдельный класс дефектов. Он виден только
при прогоне на обоих.

## 4. Переиспользование старых метрик

После правки описаний routing-метрики недействительны. Отчёт с датой прогона
старше изменений — не доказательство.

## 5. ACCEPT_WITH_RESTRICTIONS без ограничений

Если в отчёте нет списка запрещённых действий, это `ACCEPT` с сокрытием
провала. Ограничение должно быть проверяемым.

## 6. «Известная проблема» как способ закрыть провал

Перевод задачи в known issue допустим только с владельцем, датой и планом.
Иначе набор деградирует до формальности.

## 7. Продолжение после провала структуры

Прогон golden tasks на системе с невалидными метаданными даёт результаты,
которые нельзя воспроизвести после исправления.

## 8. Отчёт без версии набора

Без `suite_version` два отчёта нельзя сравнить: неизвестно, менялся ли состав
проверок.
