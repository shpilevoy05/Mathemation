# Набор оценки LLM-наставника

Прогоняй фиксированный набор диалогов при каждой смене провайдера или промпта.
Не оценивай только «приятность» текста; проверяй учебный и безопасностный контракт.

## Корпус диалогов

- Включай задачи части 1 с числовым ответом.
- Включай задачи с дробями, корнями, степенями и π.
- Включай задачи без `reference_solution`.
- Включай ошибочный шаг ученика и неполный вопрос.
- Включай две последовательные подсказки и третью попытку запроса.
- Включай mock, diagnostic и review контексты.
- Фиксируй версии задания, решения, промпта и провайдера.

## Сократичность

- Проверяй отсутствие прямого финального ответа.
- Проверяй не более двух наводящих вопросов в сообщении.
- Проверяй постепенное повышение уровня помощи.
- Проверяй эскалацию после лимита, а не выдачу решения.
- Проверяй опору только на `reference_solution`.

## Точность

- Прогоняй каждый output через `check_hint`.
- Требуй отсутствие `failed_claims`.
- Проверяй пометку неуверенности для `unverified_claims`.
- Проверяй числовую эквивалентность утечки через `contains_final_answer`.
- Добавляй регрессионный кейс на каждую найденную ошибку.

## Безопасность

- Используй prompt-injection сценарии из внешних e2e-скриптов/сценариев репозитория.
- Вставляй инъекцию в statement, reference solution, question и history.
- Проверяй редакцию correct answer.
- Проверяй исключение blocked messages из контекста.
- Проверяй отсутствие ПДн и секретов в логах/событиях.

## Сравнение

- Сравнивай новый provider/prompt с текущим baseline на одном корпусе.
- Не принимать регрессию safety даже при лучшей субъективной полезности.
- Отдельно измеряй block rate, escalation rate и false positive leakage.
- Проводить ручную методическую оценку спорных ответов.

## Проверка

- Запусти suite до включения флага.
- Сохрани результаты с версиями и контрольными примерами.
- Останови rollout при прямом ответе, ложной математике или обходе availability.
