# Версии и воспроизводимость модели

Требуй воспроизводимость каждого прогноза и потолка.
Считай результат функцией версии кода, состояния ученика, параметров и таблицы года.

## Обязательный provenance

- Фиксируй версию кода движка `apps/engine/`.
- Фиксируй snapshot mastery с `node_id`, значением и временем.
- Фиксируй полный `EngineParams` из `apps/engine/dto.py`.
- Фиксируй год и версию `PRIMARY_TO_SCALED`.
- Фиксируй forecast calibration ученика.
- Фиксируй входные weekly_hours, exam_date и структуру task weights для потолка.

## События

- Пиши версию алгоритма в payload каждого события пересчёта прогноза.
- Добавь тип события через `Event.Type` и миграцию choices, если его ещё нет.
- Передавай только идентификаторы, версии и учебные метрики без ПДн.
- Не изменяй старый event при выпуске новой версии.
- Добавляй новое событие для повторного расчёта.
- Сохраняй idempotency key пересчёта, если обработка асинхронная.

## Артефакты

- Версионируй EMA/IRT параметры и источник их калибровки.
- Храни checksum или стабильный идентификатор таблицы года.
- Не называй только git hash достаточным: настройки и состояние тоже обязательны.
- Не полагайся на текущий `config/settings.py` для воспроизведения прошлого результата.
- Сохраняй сериализуемый manifest входов и версии схемы manifest.

## Изменения

- Повышай версию алгоритма при изменении формулы, tie-breaker или нормализации.
- Документируй ожидаемую дельту на контрольных профилях.
- Не перезаписывай исторические `ProgressSnapshot` новой формулой.
- При сравнении версий используй одинаковое входное состояние.
- Обеспечь чтение старого manifest после следующего релиза.

## Проверка

- Повтори прогноз из сохранённого manifest и сравни результат.
- Проверь детерминизм `apps/engine/tests/test_algorithms.py`.
- Проверь наличие версии в payload пересчёта.
- Проверь неизменность исторического snapshot.
- Проверь отсутствие ПДн в manifest и event payload.
