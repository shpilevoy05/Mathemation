# Приёмка банка задач

Работай с `Assignment` и `AssignmentSkillTag` из `apps/content/models.py`.
Считай публикацию задачи методическим релизом, а не сохранением строки в БД.

## Обязательные поля и связи

- Заполняй понятные `title` и `statement` без скрытых инструкций для ИИ.
- Устанавливай `exam_part` равным 1 или 2.
- Ограничивай `difficulty` диапазоном 1..5.
- Устанавливай `max_score` по структуре экзамена и критериям.
- Привязывай каждую задачу минимум к одному `KnowledgeNode` через `AssignmentSkillTag`.
- Проверяй вес каждого тега как вклад навыка в задачу; не создавай дубликат пары assignment/node.
- Сверяй `ege_task_numbers` узла в `apps/knowledge/models.py` с прототипом задачи.

## Условия публикации

- Запрещай публикацию задачи части 1 без подтверждённого `correct_answer`.
- Проверяй нормализованный ответ через `Assignment.check_answer`.
- Запрещай публикацию задачи части 2 без подтверждённых критериев оценивания.
- Храни критерии вместе с методически проверенным разбором или в проверяемой структуре review.
- Требуй `reference_solution` для задач, доступных наставнику.
- Не подменяй подтверждение методиста фактом успешного импорта.

## Дедупликация

- Нормализуй условие перед сравнением: пробелы, регистр, Unicode-символы и числа.
- Сравнивай источник, прототип ЕГЭ, структуру условия и ожидаемый ответ.
- Не создавай новый `Assignment`, если различается только форматирование.
- При реальном смысловом варианте сохраняй отдельную задачу и связь с исходным прототипом.
- Не сливай задачи с разными критериями части 2.

## Диагностика

- Включай в `DiagnosticTest` только задачи с достаточным покрытием навыков.
- Проверяй, что набор различает сильные и слабые узлы, а не меряет одну тему многократно.
- Не назначай диагностическую задачу без skill tags.
- Сверяй завершение диагностики с `apps/diagnostics/services.py`.
- Помни, что диагностика инициализирует mastery и траекторию; ошибка разметки искажает весь план.

## Проверка

- Проверь часть, сложность, максимальный балл и привязки к узлам.
- Проверь наличие correct answer для ч.1 или критериев для ч.2.
- Проверь дедупликацию на точном и форматно изменённом дубле.
- Проверь покрытие диагностического набора по узлам и кластерам.
- Проверь отображение дыр контента через `methodist_context` в `apps/web/services.py`.
