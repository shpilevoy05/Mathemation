# Контракты событий

Работай с `Event` в `apps/events/models.py` и `log_event` в `apps/events/services.py`.
Считай event log главным будущим ML-активом и неизменяемой историей.

## Append-only

- Создавай событие только через `log_event`.
- Не вызывай `Event.objects.create` из продуктового кода.
- Не изменяй существующий `Event`: `save` после создания запрещён.
- Не удаляй событие: `delete` запрещён.
- Оставляй admin read-only, как в `apps/events/admin.py`.
- Не реализуй «исправление» переписыванием истории; добавляй компенсирующее событие.

## Типы

- Используй только значения `Event.Type`.
- Добавляй новый тип в `Event.Type`, а не произвольной строкой.
- Сопровождай изменение choices миграцией.
- Называй тип завершённым доменным фактом в snake_case.
- Не переиспользуй старый тип с новым смыслом.
- Документируй обязательные и опциональные ключи payload.

## Payload

- Передавай идентификаторы, версии алгоритмов и учебные метрики.
- Запрещай имена, `full_name`, e-mail, username и phone.
- Полагайся на рекурсивную проверку `_contains_personal_data_key`, но не ограничивай ревью только ею.
- Не передавай свободный текст ученика, подсказки или сканы.
- Не помещай токены, секреты и URL с подписанными параметрами.
- Стабилизируй типы значений для аналитики.

## Полнота

- Записывай каждую попытку как `attempt_submitted` из `apps/practice/services.py`.
- Записывай блок подсказки как `hint_blocked_by_guardrail`.
- Записывай изменения траектории, плана, review, XP и пробники.
- Не допускай успешной доменной операции без её обязательного события.
- Обеспечь идемпотентность потребителей и повторной доставки.

## Проверка

- Проверь запрет save/delete тестами `apps/events/tests.py`.
- Проверь неизвестный тип и вложенный ключ ПДн.
- Проверь обязательный event для каждого нового сценария.
- Проверь миграцию choices и обратную совместимость аналитики.
