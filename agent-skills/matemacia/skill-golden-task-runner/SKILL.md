# skill-golden-task-runner

## Назначение

Сделать прогон контрольных задач сравнимым между запусками и между агентами:
одинаковая формулировка задачи, одинаковый способ фиксации результата,
одинаковый формат вердикта. Без этого «стало лучше» остаётся мнением.

Каталог задач — [tests/golden-tasks/golden-tasks.yaml](../../tests/golden-tasks/golden-tasks.yaml).

## Когда активируется

- прогон одной или всех golden tasks;
- сравнение поведения Claude Code и Codex на одной задаче;
- проверка качества после обновления vendor-репозитория;
- подготовка данных для `skill-routing-evaluation` и
  `skill-acceptance-suite`;
- выяснение, какие скиллы реально применяются в реальной задаче;
- расследование регрессии, о которой сообщил разработчик.

## Когда не активируется

- нужны только метрики выбора скиллов по уже записанным прогонам — это
  `skill-routing-evaluation`;
- нужен сводный вердикт приёмки — это `skill-acceptance-suite`;
- проверка структуры или метаданных скилла;
- обычная разработка функции: задача решается, а не измеряется;
- анализ телеметрии за месяц — это
  `skill-observability-and-usage-analytics`.

## Входные данные

- `task_id` и формулировка задачи из каталога golden tasks;
- агент (`claude-code` или `codex`) и версия системы навыков;
- ожидаемые скиллы и затрагиваемые инварианты;
- чистое состояние рабочего дерева (прогон не смешивается с чужими правками).

## Что фиксируется

- исходный запрос дословно;
- выбранные скиллы;
- порядок их применения;
- прочитанные файлы;
- внесённые изменения;
- запущенные проверки;
- нарушенные или соблюдённые инварианты;
- время выполнения;
- стоимость и объём токенов;
- ручные вмешательства;
- итоговый вердикт ревьюера.

## Процедура

1. Начать с чистого рабочего дерева и зафиксировать версию системы навыков.
2. Передать агенту формулировку задачи без подсказок о нужных скиллах.
3. Не вмешиваться; каждое вынужденное вмешательство записать в
   `manual_interventions`.
4. По завершении сохранить результат в
   `reports/acceptance/golden-run-<agent>-<дата>.yaml`.
5. Сравнить `selected_skills` с `expected_skills`, заполнить
   `missing_skills` и `unexpected_skills`.
6. Проверить инварианты задачи; нарушение продуктового или security-инварианта
   даёт `result: fail` с severity `critical`.
7. Откатить изменения рабочего дерева перед следующей задачей.

## Ожидаемый результат

```yaml
task_id: GT-001
agent: claude-code | codex
selected_skills:
  - ...
expected_skills:
  - ...
missing_skills: []
unexpected_skills: []
result: pass | fail
review_notes: ...
```

Дополнительные поля прогона (`duration_s`, `tokens`, `manual_interventions`,
`invariants_violated`, `severity`) обязательны для сравнения запусков; разбор —
в [references/examples.md](references/examples.md).

## Запрещено

- подсказывать агенту нужный скилл в формулировке задачи;
- прогонять задачу на грязном рабочем дереве;
- редактировать записанный прогон после факта;
- считать задачу пройденной при нарушенном инварианте, если код работает;
- смешивать прогоны разных версий системы навыков в одном отчёте;
- сравнивать агентов по разным формулировкам одной задачи.

## Связанные скиллы

- `skill-acceptance-suite` — заказчик прогонов и владелец сводного вердикта;
- `skill-routing-evaluation` — считает метрики по записанным прогонам;
- `skill-cross-agent-consistency` — сравнивает прогоны двух агентов;
- `skill-observability-and-usage-analytics` — использует стоимость и время;
- `skill-deprecation-and-cleanup` — получает данные о бесполезных скиллах.

## Приоритет при конфликтах

1. Продуктовые и security-инварианты Математики.
2. `skill-acceptance-suite` (состав и порядок приёмки).
3. Этот скилл (формат фиксации).
4. Vendor-рекомендации по бенчмаркам агентов.

## Критерии приёмки

- результат каждой задачи записан в обязательном формате;
- `selected_skills` и порядок применения зафиксированы фактически, а не по
  ожиданию;
- каждое ручное вмешательство отражено в отчёте;
- прогоны разных агентов сделаны по одинаковой формулировке;
- нарушение инварианта всегда даёт `fail`;
- отчёты лежат в `reports/acceptance/` и пригодны для `routing_eval.py`.
