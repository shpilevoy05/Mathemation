# Анти-паттерны метаданных

## 1. patch вместо major

Самая частая ошибка: изменение инварианта оформляется как «уточнение
формулировки». В итоге golden tasks и продукт расходятся молча.

## 2. Владелец «команда»

Без конкретной роли решение об изменении правила принимает тот, кто первым
открыл файл.

## 3. Вечный draft

Скилл со `status: draft`, который используется в работе, не имеет ни ревью, ни
владельца по существу. Либо `active`, либо не устанавливается.

## 4. Просрочка ревью как норма

`review_cycle_days` без контроля превращается в украшение. Просрочка — warning,
две просрочки — повод для `deprecated`.

## 5. Две активные версии одной области

Скиллы `mastery-bkt` и `mastery-bkt-irt-fsrs` одновременно в `active` без
`replaces` и приоритета гарантируют конфликт при каждой задаче про mastery.

## 6. Метаданные без записи в CHANGELOG

Версия поднята, изменение нигде не описано — регрессию невозможно связать с
правкой.

## 7. Правка метаданных vendor-скилла

Изменение внутри `agent-skills/vendor` теряется при обновлении и ломает
проверку 7 в CI. Все решения о vendor фиксируются в `skills.lock.yaml`.

## 8. `conflicts_with` как прогноз

Список известных конфликтов заполняется по факту разбора, иначе он
превращается в перечень «на всякий случай» и перестаёт читаться.
