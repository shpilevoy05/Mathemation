# Прогноз и потолок

Различай текущий условный прогноз и максимально достижимый потолок.
Используй `apps/engine/forecast.py`, `apps/engine/ceiling.py` и адаптер `apps/progress/services.py`.

## Прогноз

- Вычисляй ожидаемый первичный балл через `expected_primary`.
- Применяй годовую таблицу через `scaled_score`.
- Ограничивай результат диапазоном [0, MAX].
- Требуй монотонность: рост mastery не должен снижать прогноз без явной причины.
- Учитывай калибровку ученика после пробников, но не выходи за допустимый диапазон.
- Не смешивай прогноз с `target_score`.

## Потолок

- Моделируй доступные узлы через `simulate_ceiling`.
- Учитывай дни до экзамена, недельные часы, стоимость узла и prerequisite edges.
- Не назначай зависимый узел до достижения `min_mastery` пререквизита.
- Гарантируй, что потолок не ниже текущего прогноза.
- Гарантируй, что больше часов не даёт более низкий потолок.
- Гарантируй свойство «Больше времени → потолок не ниже».
- Возвращай списки достижимых и недостижимых узлов для объяснения результата.

## Коммуникация

- Всегда используй формулировку «при текущем темпе».
- Не обещай экзаменационный балл и не используй язык гарантии.
- Объясняй, какие mastery, время и узлы ограничивают результат.
- Показывай изменение при движении рычагов weekly_hours/exam_date.
- Не скрывай uncertainty одной точной цифрой.
- Показывай причинность без раскрытия технической внутренности модели.

## Версионирование

- Фиксируй версию движка, `EngineParams` и годовую таблицу.
- Не пересчитывай исторический snapshot новой формулой без отдельной версии.
- Пиши версию алгоритма в событие пересчёта.
- Сохраняй входное состояние mastery для воспроизводимости.

## Проверка

- Проверь монотонность по mastery.
- Проверь границы [0, MAX] и ceiling ≥ forecast.
- Проверь монотонность потолка по часам и времени.
- Проверь порог пререквизита и недостижимый узел.
- Проверь текст «при текущем темпе» в API и UI.
