# Архитектурные границы

Сохраняй модульный монолит на Django и Python.
Считай границы приложений в `apps/` границами доменов.
Не создавай микросервисы и не разрывай Python-бэкенд без доказанного потолка.

## Модули

- Помещай модели и бизнес-операции в приложение-владельца домена.
- Не создавай дублирующую модель ради удобства соседнего приложения.
- Следуй реальным сервисным слоям `apps/planning/services.py` и `apps/practice/services.py`.
- Оставляй views, API, сериализаторы, admin и шаблоны тонкими.
- Используй `apps/web/services.py` только для read-side композиции кабинета.
- Не прячь мутацию домена в шаблоне или context builder.

## Кросс-модульные вызовы

- Вызывай другой модуль через его публичную сервисную функцию.
- Не изменяй чужую модель напрямую, если у владельца есть сервис операции.
- Передавай явные аргументы и DTO на границе.
- Избегай циклических импортов; локальный импорт допустим для разрыва цикла, но не заменяет дизайн.
- Сохраняй запись событий через `apps/events/services.py`.
- Сохраняй попытки через `apps/practice/services.py` и вердикт через `apps/expert_review/services.py`.

## Чистый движок

- Держи `apps/engine/` чистым Python без Django ORM и настроек.
- Передавай `NodeState`, `EdgeDTO`, `TaskWeight` и `EngineParams` из `apps/engine/dto.py`.
- Не импортируй `django` или другие `apps.*` из модулей движка.
- Сохраняй архитектурный тест `apps/engine/tests/test_purity.py`.
- Покрывай алгоритмы database-free тестами в `apps/engine/tests/test_algorithms.py`.

## Когда выделять сервис

- Рассматривай выделение только при реальном потолке отдельного модуля.
- Для наставника потолком может быть GPU или изоляция провайдера.
- Для движка потолком может быть подтверждённая нагрузка.
- Сначала измерь предел и зафиксируй контракт, состояние и отказоустойчивость.
- Не выделяй сервис ради моды, гипотетического масштаба или организационной симметрии.

## Запреты

- Не вводи Node-бэкенд рядом с Python-ML на старте.
- Не вводи новую зависимость без одобрения.
- Не вводи отдельную графовую или векторную БД без доказанной необходимости.

## Проверка

- Проверь владельца каждой новой сущности и операции.
- Проверь только сервисные кросс-модульные вызовы.
- Запусти purity-тест движка.
- Обоснуй любую новую границу измеренным ограничением.
