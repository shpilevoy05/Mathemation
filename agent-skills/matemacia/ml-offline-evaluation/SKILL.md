# Офлайн-оценка ML

Используй append-only историю `apps/events/` как первичный временной источник.
Не объявляй модель лучше без временного бэктеста и независимой выборки.

## Датасет

- Строй выборку только из событий, доступных на момент прогнозирования.
- Связывай `attempt_submitted` с задачей, узлами, контекстом и последующим исходом.
- Используй экспертную метку части 2 только после `expert_review_completed`.
- Фиксируй временной cutoff для каждой строки.
- Исключай ПДн и свободные тексты из аналитического датасета.
- Проверяй полноту и уникальность событий до обучения.

## Leakage

- Не используй будущий пробник для признаков предыдущего прогноза.
- Не включай итоговый балл или expert verdict в признаки до времени их появления.
- Не смешивай повторные попытки одной задачи между train и test ученика.
- Разделяй по времени и при необходимости по ученику/задаче.
- Не калибруй на test-наборе.
- Не выбирай гиперпараметры по финальной контрольной выборке.

## Метрики

- Сравнивай с текущим bootstrap baseline из `apps/engine/forecast.py`.
- Для вероятности правильного ответа считай Brier score и log-loss.
- Для балла считай MAE и калибровку по диапазонам.
- Для планировщика оценивай достижение mastery/балла при одинаковом бюджете времени.
- Показывай метрики по части экзамена, difficulty и skill cluster.
- Добавляй доверительные интервалы или bootstrap uncertainty.

## Процесс

- Версионируй срез событий, код признаков, параметры и модель.
- Запускай оценку воспроизводимо на зафиксированном snapshot.
- Не оценивай качество на train.
- Не выкатывай модель, ухудшающую guardrail-метрики подготовки.
- Документируй отличие offline proxy от реального учебного эффекта.

## Проверка

- Проверь временной cutoff и leakage тестами.
- Проверь независимый test и неизменность его меток.
- Проверь baseline, Brier/log-loss и сегменты.
- Проверь воспроизводимость артефакта и отчёта.
