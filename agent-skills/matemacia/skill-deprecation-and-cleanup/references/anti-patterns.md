# Анти-паттерны вывода навыков из эксплуатации

## 1. Удаление в день deprecation

Задачи, начатые до изменения, теряют правило на полпути. Переходный период —
не формальность.

## 2. Потеря правил при объединении

Самый дорогой анти-паттерн: скилл удалён, а его запрет («не выдавать финальный
ответ», «не рефакторить без тестов») никуда не перенесён. Список перенесённых
правил обязателен.

## 3. Удаление только из установленного каталога

Vendor-скилл, оставшийся в `skills.lock.yaml`, вернётся при следующей
установке. Lock и каталоги меняются одновременно.

## 4. Две активные версии одной области

`mastery-bkt` и `mastery-bkt-irt-fsrs` в `active` без `replaces` — конфликт при
каждой задаче про mastery.

## 5. Удаление по нулевой частоте

Сценарии инцидентов и откатов активируются редко. Метрика предлагает кандидата,
решение принимается по содержанию.

## 6. Deprecation вместо правки описания

Шумный скилл сначала сужается. Удаление полезного правила из-за плохой
формулировки — потеря.

## 7. Ссылки на удалённый скилл

После удаления `depends_on`, `replaces` и тексты `SKILL.md` не должны содержать
имя удалённого скилла: валидатор даст битую ссылку, агент — неверную гипотезу.

## 8. Удаление критического скилла без анализа зависимостей

Критический скилл почти всегда упомянут в нескольких других. Анализ
зависимостей — до, а не после.
