# skill-cross-agent-consistency

## Назначение

Разделить расхождения между агентами на допустимые (стиль, промежуточные
рассуждения, выбор вспомогательных vendor-скиллов) и недопустимые (инварианты,
security, формат данных, алгоритмические свойства, критерии допуска в
production) — и не выпускать систему навыков с недопустимыми расхождениями.

Кейсы — в [tests/cross-agent](../../tests/cross-agent).

## Когда активируется

- плановая приёмка системы навыков;
- обновление собственных или vendor-скиллов;
- разработчик сообщает «в Codex получилось иначе»;
- один агент нарушил инвариант, второй — нет;
- набор установленных скиллов или их версии могли разойтись между
  `.claude/skills` и `.agents/skills`;
- готовится решение о допуске изменения в production.

## Когда не активируется

- работа ведётся с одним агентом и вопрос не про сравнение;
- нужен разбор конфликта инструкций внутри одного агента — это
  `skill-conflict-resolution`;
- нужны метрики выбора скиллов для одного агента — это
  `skill-routing-evaluation`;
- различие только в формулировке ответа при одинаковом результате;
- расхождение вызвано разными версиями установленных скиллов — сначала
  `skills-ci-integrity` и `install-skills.ps1`.

## Входные данные

- прогоны golden tasks по обоим агентам (`skill-golden-task-runner`);
- routing-метрики по обоим агентам;
- составы `.claude/skills` и `.agents/skills` с версиями;
- перечень критических правил, которые обязаны совпадать.

## Проверяемые аспекты

- одинаковый набор установленных skills;
- одинаковые версии собственных skills;
- одинаковая интерпретация продуктовых инвариантов;
- одинаковое соблюдение запрета раскрытия ответа;
- одинаковая логика версионирования графа и экзамена;
- одинаковое соблюдение object permissions;
- одинаковая реакция на prompt injection;
- одинаковая обработка критических миграций и релизов.

## Допуск различий

Различаться могут:

- стиль плана;
- структура промежуточного рассуждения;
- конкретная реализация при одинаковом контракте;
- выбор некритичных вспомогательных vendor-skills.

Не могут различаться:

- продуктовые инварианты;
- security-ограничения;
- формат доменных данных;
- алгоритмические свойства;
- критерии допуска в production.

## Процедура

1. Сверить составы и версии установленных скиллов; при расхождении —
   переустановить и повторить.
2. Прогнать одинаковые формулировки на обоих агентах.
3. Сравнить результаты по каждому аспекту из списка выше.
4. Классифицировать каждое расхождение как допустимое или недопустимое.
5. Для недопустимого — найти причину: описание скилла, разная область
   применения, vendor-скилл, доступный только одному агенту.
6. Устранить причину в скилле, а не в конкретном агенте.
7. Записать отчёт; разборы — в [references/examples.md](references/examples.md).

## Ожидаемый результат

```yaml
suite: cross-agent
run_at: 2026-07-30
installed_sets_identical: true
version_mismatches: []
divergences:
  - aspect: продуктовые инварианты
    task_id: GT-011
    claude_code: соблюдён
    codex: нарушен
    verdict: недопустимо
    cause: "description socratic-tutor-rag без триггеров задачи"
    action: "уточнить description, версия minor"
allowed_divergences:
  - aspect: выбор вспомогательного vendor-скилла
recommendation: BLOCK | ALLOW
```

## Запрещено

- объявлять расхождение допустимым, если оно касается инварианта, security,
  формата данных или алгоритмических свойств;
- исправлять расхождение инструкцией «для Codex делай иначе» внутри скилла;
- держать разные наборы или версии скиллов в двух целевых каталогах;
- сравнивать агентов по разным формулировкам задачи;
- закрывать расхождение без указания причины;
- допускать изменение в production при недопустимом расхождении.

## Связанные скиллы

- `skill-golden-task-runner` — источник сопоставимых прогонов;
- `skill-routing-evaluation` — сравнение метрик выбора;
- `skills-ci-integrity` — гарантирует идентичность каталогов установки;
- `skill-acceptance-suite` — включает consistency tests в приёмку;
- `skill-structure-validator` — правки описаний по итогам разбора.

## Приоритет при конфликтах

1. Продуктовые и security-инварианты Математики.
2. Этот скилл: недопустимое расхождение блокирует допуск.
3. `skill-acceptance-suite`.
4. Рекомендации, специфичные для одного агента.

## Критерии приёмки

- составы и версии скиллов в обоих каталогах совпадают;
- по каждому критическому аспекту есть результат для обоих агентов;
- каждое расхождение классифицировано и имеет причину;
- недопустимые расхождения дают `recommendation: BLOCK`;
- исправление внесено в скилл, а не в поведение отдельного агента;
- отчёт сохранён в `reports/acceptance/`.
