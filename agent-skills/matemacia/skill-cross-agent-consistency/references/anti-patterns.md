# Анти-паттерны сравнения агентов

## 1. Инструкция «для одного агента»

`Если ты Codex — делай иначе` создаёт два разных правила и гарантирует
расхождение в следующей задаче. Правило одно; различаться может реализация.

## 2. Расхождение объявлено допустимым «потому что мелкое»

Критерий не размер, а класс: инвариант, security, формат данных,
алгоритмические свойства, критерии допуска. Всё перечисленное — недопустимо.

## 3. Сравнение при разных наборах скиллов

Самая частая причина расхождения — разные версии в `.claude/skills` и
`.agents/skills`. Сначала выравнивание, потом выводы.

## 4. Разные формулировки задачи

Переформулировка «под агента» делает сравнение недействительным.

## 5. Расхождение без причины

Запись «Codex ведёт себя иначе» не приводит к правке. Причина выбирается из
списка: описание скилла, область применения, доступность vendor-скилла,
разные версии.

## 6. Исправление на стороне агента

Настройка одного агента маскирует дефект описания скилла. Через месяц дефект
проявится у второго.

## 7. Приёмка по одному агенту

Класс дефектов «агенты понимают правило по-разному» не обнаруживается в
принципе.
