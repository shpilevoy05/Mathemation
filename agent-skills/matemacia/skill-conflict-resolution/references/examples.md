# Примеры разрешения конфликтов

## 1. Vendor PostgreSQL против собственной модели событий

Vendor-скилл: «храните события аналитики в одной широкой таблице с JSONB».
Собственный `event-contracts-analytics`: «каждое событие версионировано,
схема фиксирована, изменение схемы — новая версия события».

```yaml
conflict:
  skills:
    - event-contracts-analytics
    - postgres-best-practices
resolved_by: event-contracts-analytics
reason: "Собственный доменный skill выше vendor-скилла технологии"
constraints_preserved:
  - индексы и партиционирование по рекомендациям vendor-скилла
  - VACUUM-политика из vendor-скилла
```

Проигравший скилл сохраняет всё, что не касалось предмета конфликта.

## 2. Frontend-скилл против дизайн-системы

Vendor frontend-скилл предлагает компонент со своей типографикой и палитрой.
Собственный ux-скилл задаёт дизайн-систему Математики.

```yaml
conflict:
  skills:
    - matemacia-design-system
    - vendor-frontend-components
resolved_by: matemacia-design-system
reason: "Продуктовый уровень: единый визуальный язык — часть продукта"
constraints_preserved:
  - структура компонента и правила доступности из vendor-скилла
  - требования к клавиатурной навигации
```

## 3. Общий LLM-скилл против сократического наставника

Общий скилл допускает выдачу готового решения. `socratic-tutor-rag` это
запрещает.

```yaml
conflict:
  skills:
    - socratic-tutor-rag
    - vendor-llm-prompting
resolved_by: socratic-tutor-rag
reason: "Запрет выдачи финального ответа — продуктовый инвариант"
constraints_preserved:
  - структура промпта и защита от prompt injection из vendor-скилла
```

Компромисс «выдать решение, но мелким шрифтом» недопустим.

## 4. ML-скилл против требования калибровки

ML-скилл предлагает максимизировать accuracy прогноза балла. Продуктовый
скилл требует калиброванного и объяснимого прогноза с потолком.

```yaml
conflict:
  skills:
    - score-forecast-and-ceiling
    - vendor-ml-optimization
resolved_by: score-forecast-and-ceiling
reason: "Калибровка и объяснимость — продуктовый инвариант; accuracy вторична"
constraints_preserved:
  - схема кросс-валидации из vendor-скилла
  - контроль утечки признаков
```

## 5. Ложный конфликт

Скилл A требует идемпотентности Celery-задачи, скилл B — ретраев с
экспоненциальной задержкой. Требования совместимы: идемпотентность и ретраи
реализуются вместе. Запись о конфликте не создаётся, оба требования
выполняются.

## 6. Равный уровень, разная узость

Два собственных доменных скилла: `mastery-bkt-irt-fsrs` (узкий: обновление
mastery) и `adaptive-planner` (широкий: планирование). Конфликт по формуле
обновления решается в пользу узкого скилла; планировщик получает результат как
входные данные.
